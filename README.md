Online Course Registration System - UI/UX Prototype

Repository/Project Purpose:
This folder contains a browser-based draft UI/UX prototype for the Online Course Registration System. The screens support student registration, course search, instructor schedule review, and section enrollment viewing.

Team Member Contributions:
- Bryan Ly: Completed the full UI/UX prototype package, including the Home Screen, Course Search Screen, Student Registration Screen, Instructor Schedule Screen, Session Enrollment Screen, shared CSS styling, basic JavaScript validation, and README documentation.

Screen Summary:
1. index.html - Home screen with navigation to all core functions and a simple task flow overview.
2. course-search.html - Allows users to search summer courses by department, instructor, or course number and view course details.
3. student-registration.html - Allows a student to view enrolled sections and register for available sections.
4. instructor-schedule.html - Allows an instructor to view assigned summer course sections.
5. session-enrollment.html - Allows authorized users to view students enrolled in a selected section.

HTML/CSS/JS Elements and Techniques Used:
- Semantic HTML5 structure with header, nav, main, section, tables, forms, labels, inputs, and buttons.
- Shared CSS file for consistent layout, font usage, navigation styling, cards, tables, buttons, badges, and responsive design.
- JavaScript arrays were used as sample course and enrollment data.
- JavaScript functions support course filtering and registration validation.
- Validation logic prevents students from registering for two sections of the same course and blocks registration when a section is full.
- Hyperlinks connect all pages so the evaluator can navigate the prototype in a browser.

Design Decisions and Challenges:
- The design uses a consistent blue-and-white color scheme to create a clean academic system style.
- Cards and tables were used to make information easy to scan quickly.
- The registration workflow was simplified so the evaluator can understand the task without a real database.
- Since this is a UI/UX draft, sample data is hard-coded instead of connected to a live backend.
- The interface was designed to support the required project rules: multiple sections, instructor assignments, enrollment limits, duplicate registration prevention, and section rosters.
